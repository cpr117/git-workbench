使用指南操作提交树对比整个项目查看代码历史有本地修改时弹窗与标签页执行 Git 操作

在提交树里定位修改

按 Cmd+Alt+G（macOS）或 Ctrl+Alt+G（Windows / Linux），打开与终端并列的底部 Git 标签。

左侧选分支→中间选提交→右侧点文件→查看 Diff

点击左侧分支只筛选日志，不会切换当前分支。底部 Git 与终端之间可以直接切换；拖动面板上边缘增加高度，或使用右上角的最大化按钮。

多选怎么看？

普通点击恢复单选；Shift 点击选择连续区间，Cmd / Ctrl 点击增减任意提交。自动显示包含最旧提交的一份累计差异。恰好选两个时，「仅比两个快照」是额外模式：它直接比较两个提交完成后的快照，不包含较旧提交相对父版本的修改。

右键分支，对比整个项目

打开底部 Git → Log，在左侧 Local / Remote / Tags 中右键具体分支。也可用 Shift+F10 打开菜单；单击分支仍然只筛选历史。

与当前分支比较

所选分支的提交快照 → 当前 HEAD 快照，只看已提交差异，不包含本地未提交改动。

与工作区比较（整个仓库）

所选分支快照 → 当前工作区，包含暂存、未暂存和未跟踪文件。比较范围是整个当前仓库，不受 Log 路径筛选限制。

左侧选文件，右侧看 Diff

源代码管理最上方出现“对比”文件树，右侧自动打开原生 Diff 标签；选择其他文件更新预览，关闭当前对比标签后，左侧自动隐藏。

分支操作的方向会写清楚

菜单同时提供检出、新建、检出并变基到当前分支、当前分支变基到所选分支、合并、上游快进更新、推送、重命名和删除。写操作执行前显示仓库及完整分支名，取消不修改仓库；重命名与推送准确作用于右键选中的分支。

对比标题中的“…”可切换树形 / 列表及按名称 / 路径 / 状态排序，旁边的折叠图标用于全部折叠。展示方式与排序会保存。平时不显示空对比视图，不再用固定说明行盖住文件名。

比较覆盖一个 Git 仓库，不递归混入独立子仓库；网页示例只用固定数据展示菜单与差异，真实编辑器里的原生文件树与 Diff 由插件打开。

查看选区、文件和当前行历史

在代码编辑器中选中一段代码，右键展开 Git Workbench 二级菜单，再选择「查看选区 / 当前行历史」。没有选区时，追溯光标所在行。

选区 / 当前行历史

基于 Git -L 追踪代码范围，在列表中切换版本，查看左右代码、历史行号和差异。

文件历史

从相同菜单选择「查看文件历史」，回看完整文件，并追踪 Git 能识别的重命名。

Blame 与作者标注

「查看当前行提交」定位作者和提交；「切换逐行作者标注」在代码旁显示 SHA 与作者。

历史列表同样支持 Shift 与 Cmd / Ctrl 多选，也可以使用 Shift+↑ / ↓。工具栏提供差异导航、仅显示改动和原始补丁。点击「在提交图查看」，跳转到底部 Git 面板。

当前代码有改动，也可以查询

无需先保存或提交。插件读取命令触发时的编辑器内容，将所选行映射回固定的 HEAD 快照，再查询已提交历史。

前面插入或删除了行
按变动后的行号映射回原位置。
选中的代码被改写
追溯修改前的整个代码块，窗口会明确说明范围。
选区包含纯新增行
新增行暂无历史；混合选区只追溯已有代码。
历史窗口显示的是已提交记录

本地改动不会伪装成提交。查询不会保存文件、改变暂存区或创建提交。纯新增文件、纯新增选区及文件末尾空行没有对应历史时，会给出提示。

插件界面跟随编辑器的显示语言。中文环境使用简体中文，英文及其他暂未支持的语言使用英文；切换应用显示语言并重新加载后生效。提交信息、路径和代码保持原样。

默认小窗，需要时切成标签页

macOS 本地工作区默认打开独立原生小窗。切换到其他应用时隐藏，返回所属编辑器后恢复，不跨应用置顶。

点击右上角「在标签页中打开」，可将这次历史移入编辑器；标签页里点击「在弹窗中打开」可切回。所选版本、多选状态和映射说明会保留。

需要以后都用标签页时，在编辑器 settings.json 中设置：

"gitWorkbench.historyPresentation": "editor"

恢复默认弹窗时，将 editor 改成 popup。不支持原生弹窗的平台不会自动新增标签页，需要显式选择 editor。远程场景尚未实机验证。

直接从目标提交执行操作

右键目标提交，按菜单创建分支或标签，或执行 Checkout、Cherry-pick、Revert、Merge、Rebase、Reset。右键会恢复单选，写操作只作用于当前目标。

提交与工作区

暂存文件、检查 Diff、提交暂存区。在编辑器选中代码后，可通过「暂存选中代码块」调用宿主 Git 的部分暂存能力。

分支与远端

右上角「Git 操作」按分类提供分支切换、Fetch、Pull、Push 和 Stash。它们会按提示作用于当前仓库。

冲突与中止

在工作区解决冲突并暂存，再选择「继续操作」；也可以中止当前 Git 操作。Merge、Rebase、Reset 的目标作用于当前分支。

面板中的网页示例只用于学习界面，不连接你的仓库。实际插件中的 Git 写操作会按提示确认；Reset、文件恢复等操作可能覆盖工作区内容。

开始使用前，
你可能想知道。

在哪里下载源码？可以自己编译吗？

从本页“源码下载”获取 ZIP，或访问 GitHub 仓库。使用 Node.js 22+ 安装依赖并编译；构建带原生历史小窗的发行包需要 macOS 和 Xcode Command Line Tools。项目按 MIT 许可证发布。

已经完全等同于 GoLand 的 Git 功能了吗？

尚未达到一比一对等。当前覆盖提交树、文件 Diff、选区历史、多选累计对比、Blame 和常用 Git 操作。暂不支持拖动提交重排、拖线合并、多选批量 Cherry-pick / Revert，以及 GoLand 的额外语义追踪。

为什么有些新增代码看不到历史？

纯新增内容尚未进入任何提交，因此没有对应的提交历史。已有代码被修改仍能通过 HEAD 映射追溯；新增与已有代码混合选择时，窗口会注明哪些部分没有历史。

为什么没有弹窗，或提示平台不支持？

原生小窗目前支持 macOS 12+ 本地桌面工作区。Windows、Linux 和 SSH / Dev Container 请在设置中显式选择 editor 模式。安装后请重新加载窗口。原生组件为 ad-hoc 签名，尚未进行 Apple Developer ID 签名和公证。

Git 面板在哪，为什么代码还在上面？

这是预期布局：提交树位于终端旁的底部 Git 标签，代码与原生 Diff 保留在上方编辑区。状态栏 Git Workbench 和打开提交图快捷键都会聚焦同一个底部视图。

支持哪些仓库和历史范围？

支持本地工作区仓库和 Git worktree。提交图默认加载 200 条，可继续加载至最多 5,000 条；历史列表和单次多选最多 300 条。复杂跨文件移动、合并与重命名遵循 Git -L / --follow 的能力边界。

代码会上传到这个介绍网站吗？

不会。Git Workbench 的查询与 Git 命令在扩展宿主所在机器执行；此网页的演示数据固定，不读取或连接你的编辑器、文件和仓库。执行 Push 等远端操作时，Git 会连接你自己配置的远端。
