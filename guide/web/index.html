几步安装，回到代码。

本指南适用于 Orbit Git 0.15.0 预发布版，扩展标识为 PRCooper.orbit-git。VS Code 可从 Marketplace 安装并选择预发布版本；Cursor、Qoder 或离线安装使用下方 VSIX 包。

Orbit Git 提供统一的文件右键菜单、历史版本切换和 10 项即时生效的模块开关。更改、提交和 Diff 继续复用编辑器原生界面，界面跟随编辑器显示语言。桌面版 VS Code 及兼容的 Cursor、Qoder 均可安装。

在提交树里定位修改

按 Cmd+Alt+G（macOS）或 Ctrl+Alt+G（Windows / Linux），打开与终端并列的底部 Git 标签。

左侧选分支→中间选提交→右侧点文件→查看 Diff

点击左侧分支只筛选日志，不会切换当前分支。底部 Git 与终端之间可以直接切换；拖动面板上边缘增加高度，或使用右上角的最大化按钮。

多选怎么看？

普通点击恢复单选；Shift 点击选择连续区间，Cmd / Ctrl 点击增减任意提交。自动显示包含最旧提交的一份累计差异。恰好选两个时，「仅比两个快照」是额外模式：它直接比较两个提交完成后的快照，不包含较旧提交相对父版本的修改。

右键分支，对比整个项目

打开底部 Git → Log，在左侧 Local / Remote / Tags 中右键具体分支。也可用 Shift+F10 打开菜单；单击分支仍然只筛选历史。

与当前分支比较

所选分支的提交快照 → 当前 HEAD 快照，只看已提交差异，不包含本地未提交改动。

与工作区比较（整个仓库）

所选分支快照 → 当前工作区，包含暂存、未暂存和未跟踪文件。比较范围是整个当前仓库，不受 Log 路径筛选限制。

左侧选文件，右侧看 Diff

源代码管理最上方出现“对比”文件树，右侧自动打开原生 Diff 标签；选择其他文件更新预览，关闭当前对比标签后，左侧自动隐藏。

分支操作的方向会写清楚

菜单同时提供检出、新建、检出并变基到当前分支、当前分支变基到所选分支、合并、上游快进更新、推送、重命名和删除。写操作执行前显示仓库及完整分支名，取消不修改仓库；重命名与推送准确作用于右键选中的分支。

对比标题中的“…”可切换树形 / 列表及按名称 / 路径 / 状态排序，旁边的折叠图标用于全部折叠。展示方式与排序会保存。图标样式也可在同一菜单中切换，详见下节。平时不显示空对比视图，不再用固定说明行盖住文件名。

比较覆盖一个 Git 仓库，不递归混入独立子仓库；网页示例只用固定数据展示菜单与差异，真实编辑器里的原生文件树与 Diff 由插件打开。

选择对比文件树的图标样式

先打开一次分支或目录对比，在左侧“对比”标题右侧点击 …，选择以下任意一种样式；立即生效，并在重新加载后保留。

文件图标（与更改一致） · 默认

跟随编辑器当前的文件图标主题，按 Go、TypeScript、JSON 等文件类型显示图标。右侧显示 A / M / D / R 等标记，分别表示新增、修改、删除和重命名。

变更状态图标

使用原有的彩色加减图标，并在文件名后显示“新增 / 修改 / 删除”等状态文字。

两种样式都支持树形 / 列表与排序，点击文件仍在右侧打开原生 Diff。状态来自本次比较，不会混入当前工作区的状态。

也可在设置中搜索 gitWorkbench.comparisonIconStyle：file 为默认文件图标，status 为变更状态图标。

"gitWorkbench.comparisonIconStyle": "file"

查看选区、文件和当前行历史

在代码编辑器中选中一段代码，右键展开 Orbit Git 二级菜单，再选择「查看选区 / 当前行历史」。没有选区时，追溯光标所在行。

选区 / 当前行历史

基于 Git -L 追踪代码范围，在列表中切换版本，查看左右代码、历史行号和差异。

文件历史

从相同菜单选择「查看文件历史」，回看完整文件，并追踪 Git 能识别的重命名。

Blame 与作者标注

「查看当前行提交」定位作者和提交；「切换逐行作者标注」在代码旁显示 SHA 与作者。

历史列表同样支持 Shift 与 Cmd / Ctrl 多选，也可以使用 Shift+↑ / ↓。点击较新 / 较旧按钮或按 ↑ / ↓ 切换版本；搜索后只在筛选结果间切换。工具栏提供差异导航、仅显示改动和原始补丁。点击「在提交图查看」，跳转到底部 Git 面板。

当前代码有改动，也可以查询

无需先保存或提交。插件读取命令触发时的编辑器内容，将所选行映射回固定的 HEAD 快照，再查询已提交历史。

前面插入或删除了行
按变动后的行号映射回原位置。
选中的代码被改写
追溯修改前的整个代码块，窗口会明确说明范围。
选区包含纯新增行
新增行暂无历史；混合选区只追溯已有代码。
历史窗口显示的是已提交记录

本地改动不会伪装成提交。查询不会保存文件、改变暂存区或创建提交。纯新增文件、纯新增选区及文件末尾空行没有对应历史时，会给出提示。

跟随应用的显示语言

插件读取 VS Code、Cursor 或 Qoder 的应用显示语言：中文环境使用简体中文，英文及其他暂未支持的语言使用英文，无需另设插件语言。

在应用设置中更改显示语言，或从命令面板运行 Configure Display Language / 配置显示语言（宿主提供时），选择语言后按提示重新加载窗口。

语言切换覆盖功能菜单、Git 提交图、对比文件树和历史小窗 / 标签页。分支名、提交信息、作者、路径和代码保持原样；它与代码文件的语言模式无关。

默认小窗，需要时切成标签页

macOS 本地工作区默认打开独立原生小窗。切换到其他应用时隐藏，返回所属编辑器后恢复，不跨应用置顶。

点击右上角「在标签页中打开」，可将这次历史移入编辑器；在 macOS 本地工作区，标签页里点击「在弹窗中打开」可切回；其他环境隐藏此按钮。所选版本、多选状态和映射说明会保留。

需要以后都用标签页时，在编辑器 settings.json 中设置：

"gitWorkbench.historyPresentation": "editor"

恢复默认弹窗时，将 editor 改成 popup。不支持原生弹窗的环境或首次小窗启动失败时会自动使用标签页。手动切换小窗失败会保留原标签页及所选版本。远程场景尚未实机验证。

查看与恢复 Stash

在底部 Git → Stash 中，左侧选择记录，右侧显示该记录的变更目录树。可筛选路径、展开或折叠目录；点击文件打开原生 Diff，右键记录可在新标签页查看差异。

Apply / Pop

Apply 恢复后保留记录；Pop 仅在恢复成功后删除。发生冲突会保留 Stash，方便继续处理。

Unstash…

可选择恢复原暂存状态、恢复成功后是否删除记录，或从原始基线恢复到新分支。新分支恢复前需要干净的工作区。

Drop

确认后删除所选记录。列表变化时会重新校验，避免因编号移动而删除其他记录。

其他入口操作后也会自动同步

在原生“更改”、终端或其他工具创建、Pop、删除、清空 Stash 后，列表自动更新。切入 Stash、重新显示 Git 面板或返回编辑器时也会补查；列表未变化时保留当前详情。

未跟踪文件与暂存区独有修改会标明来源。同路径的不同来源分别显示；共享同一仓库的 Git worktree 使用同一份 Stash 列表。网页演示只有固定数据，不执行恢复或删除。

文件、文件夹和项目使用同一套右键菜单

在资源管理器中右键目标，展开 Orbit Git。单个文件也支持提交、添加到暂存区、本地排除、显示差异、与版本 / 分支比较、文件历史、回滚和 Stash。

先选择范围

文件操作针对该文件，目录操作针对目录内文件；打开整个项目对比也可在底部 Git 中右键分支。

沿用原生 Diff

比较文件时直接打开原生 Diff；比较目录或项目时，在左侧“对比”文件树选择文件，右侧查看修改。

提交文件只包含该文件当前已保存的内容，其他已暂存文件不纳入。范围 Stash 前，其他文件有已暂存改动会提示先取消暂存；重命名涉及范围外路径时，请在共同父目录执行写操作。

推送、拉取、合并和 Unstash 等仓库级操作仍作用于目标所属的整个 Git 仓库。写操作前请核对提示的仓库、路径和影响范围。

用一个列表管理 10 个功能模块

从命令面板运行 Orbit Git: 功能开关，或点击底部 Git 面板的齿轮。也可在编辑器设置中搜索 gitWorkbench.modules，直接在同一个紧凑列表中勾选。

  • 提交树与分支、选区与当前行历史、文件历史、作者标注
  • 文件与目录对比、Stash、Git 写操作
  • 资源管理器右键菜单、编辑器右键菜单、状态栏入口

全部默认启用，修改立即生效，无需重新加载。关闭菜单或状态栏入口后，仍可从命令面板重新启用；关闭历史或对比模块会关闭相应视图，关闭作者标注会清除现有标注。

Git 写操作的范围

停用后，插件内的提交、暂存、同步、分支及 Stash 写操作不可执行；编辑器原生 Git 不受影响，已经启动的 Git 进程会继续完成。

升级时自动合并旧版开关，保留勾选状态与用户 / 工作区作用域，统一存入一个配置对象。

直接从目标提交执行操作

右键目标提交，按菜单创建分支或标签，或执行 Checkout、Cherry-pick、Revert、Merge、Rebase、Reset。右键会恢复单选，写操作只作用于当前目标。

更改与提交

点击底部 Git 的“更改 ↗”打开原生源代码管理，在“更改”中查看文件树和 Diff、暂存与提交。在编辑器选中代码后，可通过「暂存选中代码块」调用宿主 Git 的部分暂存能力。

分支与远端

右上角「Git 操作」按分类提供分支切换、Fetch、Pull、Push 和 Stash。它们会按提示作用于当前仓库。

冲突与中止

在工作区解决冲突并暂存，再选择「继续操作」；也可以中止当前 Git 操作。Merge、Rebase、Reset 的目标作用于当前分支。

面板中的网页示例只用于学习界面，不连接你的仓库。实际插件中的 Git 写操作会按提示确认；Reset、文件恢复等操作可能覆盖工作区内容。

开始使用前，
你可能想知道。

在哪里下载源码？可以自己编译吗？

从本页“源码下载”获取 ZIP，或访问 GitHub 仓库。使用 Node.js 22+ 安装依赖并编译；构建带原生历史小窗的发行包需要 macOS 和 Xcode Command Line Tools。项目按 MIT 许可证发布。

已经完全等同于 GoLand 的 Git 功能了吗？

尚未达到一比一对等。当前覆盖提交树、文件 Diff、选区历史、多选累计对比、Blame 和常用 Git 操作。暂不支持拖动提交重排、拖线合并、多选批量 Cherry-pick / Revert，以及 GoLand 的额外语义追踪。

为什么有些新增代码看不到历史？

纯新增内容尚未进入任何提交，因此没有对应的提交历史。已有代码被修改仍能通过 HEAD 映射追溯；新增与已有代码混合选择时，窗口会注明哪些部分没有历史。

为什么没有弹窗，或提示平台不支持？

原生小窗支持 macOS 12+ 本地桌面工作区。Windows、Linux 和 SSH / Dev Container 自动使用标签页。安装后请重新加载窗口。原生组件为 ad-hoc 签名，尚未进行 Apple Developer ID 签名和公证。

Git 面板在哪，为什么代码还在上面？

这是预期布局：提交树位于终端旁的底部 Git 标签，代码与原生 Diff 保留在上方编辑区。状态栏 Orbit Git 和打开提交图快捷键都会聚焦同一个底部视图。

支持哪些仓库和历史范围？

支持本地工作区仓库和 Git worktree。提交图默认加载 200 条，可继续加载至最多 5,000 条；历史列表和单次多选最多 300 条。复杂跨文件移动、合并与重命名遵循 Git -L / --follow 的能力边界。

代码会上传到这个介绍网站吗？

不会。Orbit Git 的查询与 Git 命令在扩展宿主所在机器执行；此网页的演示数据固定，不读取或连接你的编辑器、文件和仓库。执行 Push 等远端操作时，Git 会连接你自己配置的远端。
